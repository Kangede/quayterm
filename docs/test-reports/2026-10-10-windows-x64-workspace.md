## 首次失败与修正

1. Windows 文件驱动首轮 6 PASS / 2 FAIL / 2 未运行。SFTP 初始路径为 `/tmp/...`，显式导航为 `/c/...`，Linux 用例的期望却按本地 Windows 路径比较。精确适配服务端路径后，源码/包各 10/10；未删断言或改路径业务逻辑。
2. 真实复用器驱动先把 Electron evaluate 的注入参数当成日志偏移；其后滚轮进入 tmux copy mode，Escape 并非该环境的可靠退出键；分离后立即发命令又早于 PTY 交接。修正参数、限定专用 socket 退出 copy mode、等待实际 Attached/Detached 状态后，最终完整 7 组通过。原失败有脱敏摘要和日志哈希。
3. 私有剪贴板备份辅助脚本初次使用 Electron 44 已不存在的 API，启动失败。后续使用当前 API 清除本轮标记。**本轮确实改写过系统剪贴板，没有声称恢复测试前全部格式。** 不是产品问题。
4. 系统图像捕获及一次关闭快捷键超时属于原生工具限制。记事本用同一工具的实际辅助文本验证；无画面证据的 PNG/PDF 保留 BLOCKED。收尾时只定向关闭已保存、路径/PID 确认属于本轮的查看器。
