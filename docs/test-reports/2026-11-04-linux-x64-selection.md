- Linux x64，Ubuntu 26.04.1，Node 22.23.2，Electron 44.7.0；真实桌面及一次性回环 SSH/SFTP 服务。
- 基线：`b1139ec4c7e2a5139ddc7265017c7b37199ebc11`（v0.2.4）。受测修复提交：`21e908446e2f6912063668554a116ea35bf68226`（版本字符串 0.2.5）。
- 使用独立配置、临时文件目录和测试会话，没有操作用户 LAN 主机或日常配置。

## 复现与修复

在真实 SFTP 服务中建立 `selection/a.txt`、`b.txt`、`c.txt`，展开文件侧栏的 `selection` 目录，单击 `a.txt` 后 Shift 单击 `c.txt`。v0.2.4 应选中三项，实际选区为空；基线新增回归用例明确失败，证据见 `baseline-e2e.log`、`baseline-e2e.json` 和 `ui-run/baseline-results/`。

原因是旧实现仅在顶层目录数组里查找范围，展开后的子文件索引均为 -1；同时将已选数组第一项当作起点，反向选取后继续调整范围时起点会移动。

修复后显示和选区计算共用可见目录树，单独保存选择起点。折叠、隐藏、过滤或删除后不可见的条目退出选区，失效起点不再参与范围计算。起点随会话侧栏状态一起恢复；普通点击、Ctrl/⌘ 逐项选择、右键已有多选以及当前目录顶层全选行为保留。

覆盖的选择行为：

- 展开目录内正向选取、反向选取、继续缩小或扩大范围、重复选择同一区间。
- 多层嵌套目录和相邻展开分支之间，按屏幕显示顺序选择连续范围。
- Ctrl/⌘ 单击增减条目及随后 Shift 选择；右键已选条目保留整个选区，复制路径得到全部目标。
- 折叠子目录、隐藏点文件、过滤掉整个分支后，失效起点不会导致越界或误选。
- 全选保留当前目录顶层条目的原有语义，不重复加入目录中已展开的后代。
- 切换 SSH 会话、隐藏/恢复侧栏后保留反向选区的原始起点；进入新目录后清空旧起点。
- 普通本地/SFTP 文件列表的名称、大小排序和范围选择保持一致。
- 目录树循环的保护和路径去重由逻辑测试覆盖，不据此声称所有符号链接场景均完成桌面验收。

完整桌面回归还包括原有文件上传下载、覆盖确认、外部打开、主题、tmux/screen、拖动分屏、空面板收起、重连和大输出。

## 首轮 CI 与测试驱动修正

[首轮 Actions 41849062684](https://github.com/Kangede/quayterm/actions/runs/41849062684) 中，新增连选用例在三平台通过；macOS 的原有 `desktop-smoke.e2e.cjs` 在自动复制菜单点击后未关闭，导致该任务失败。失败日志与 trace 保存在 `first-ci-macos.log`、`first-ci-macos/`，不将该轮记为全通过。

该驱动原先在打开菜单后立即定位并点击选项，没有像既有文件菜单测试那样等待进场动画结束。失败 trace 中该次选项点击仅约 117 ms。现补充透明度、动画类和绘制完成等待，并增加设置实际翻转的断言及失败截图；原有菜单关闭、剪贴板、鼠标协议断言全部保留。此修正只涉及测试驱动，SFTP 产品修复保持不变；最终三平台复测结果绑定 Release 中记录的新提交与运行。

驱动修正后，本机重测原有桌面 smoke 和新增文件连选专项，2 / 2 通过（`native-smoke-sync.log`、`native-smoke-sync.json`）；类型和格式检查也通过。最终三平台通过状态以新的完整 CI 为准，不靠随机重试消除原失败记录。
