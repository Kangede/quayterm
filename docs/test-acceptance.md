# 验收用例与“测试完成”的定义

基础清单适用于 [交接指南](agent-testing.md) 指定的 v0.2.1 基线。F05 是 2026-10-09 新增的“用本地程序打开”验收，适用于 v0.2.2 之后包含此功能的源码/构建，不追溯修改旧报告的计数。新增结果使用 [报告模板](test-report-template.md)。本清单定义有限、可复现的功能验收，不宣称覆盖所有系统版本、服务端和输入法。

## 1. 状态和证据

| 状态      | 使用条件                                                                   | 是否算完成通过       |
| --------- | -------------------------------------------------------------------------- | -------------------- |
| `PASS`    | 在声明的系统、代码/产物上执行所有子步骤，预期全部满足，具有证据            | 是                   |
| `FAIL`    | 条件具备，实际结果偏离预期；记录复现、实际现象、影响                       | 否                   |
| `BLOCKED` | 缺机器/桌面/账号/服务/授权，或系统策略阻止执行；说明如何解除               | 否                   |
| `NOT_RUN` | 尚未执行，或只有不能覆盖本项的旧证据                                       | 否                   |
| `N/A`     | 该项客观不适用于当前目标；必须说明原因，例如 Windows 不适用 macOS 菜单分支 | 从分母排除；不是通过 |

没有测试设备、时间不够、CI 没配置、需要真实 PTY、只测过另一个系统都不属于 `N/A`。一项只完成部分子步骤时拆分子项记录，父项保持未完成；不得把未执行步骤省略后标 PASS。

每项证据至少能回答：何时、在哪个 OS/CPU、哪个代码提交/发行包、做了什么、实际观察到什么。自动化附命令、退出码、用例数/失败数和日志；GUI 附关键截图或录像及结果描述；文件传输附源/目标哈希；会话独立性附连接/PTY 或会话标识。截图不能证明密码加密或文件字节一致，程序退出码也不能证明手动安装流程。

失败后重跑通过不能直接抹去首次失败。说明原因、修复提交/环境变化，保留失败和复测结果；随机重试成功而无解释仍是未解决问题。

## 2. 各系统必测清单

以下各项对 Linux x64、Windows x64、macOS arm64、macOS x64 分别适用。目标 OS 的正常用户账号和真实桌面是前提。除了 A01，主验收使用发布包或明确标注的修复构建；源码运行不能代替。

每种发行格式都必须做 R01/R02。其余功能可在同架构的一种实际发行格式中完整执行，并记录另一格式的 `app.asar` 哈希和版本一致；如果不同则重测。安装/升级/卸载分支按格式单独记录。macOS arm64/x64 不能共享一次运行结果。

v0.2.1 尚未签名/公证是已知的发行状态；在正常 OS 单应用许可流程下能运行的结果可注明条件后记录，不能称为“无需提示的已签名发行”。若需要修改全局安全策略或增加 `--no-sandbox` 才能运行，则默认环境启动仍未通过。

仅在**隔离测试服务的 shell**运行以下 T04 示例。每条代表不同判据，保存命令及观察结果；不要在用户真实业务主机上执行：

```sh
printf '\033[31mANSI16\033[0m \033[38;5;214mANSI256\033[0m \033[38;2;80;200;120mRGB\033[0m\n'
printf '\033[1mBOLD\033[0m \033[4mUNDERLINE\033[0m \033[7mINVERSE\033[0m\n'
printf '中文 🌏 e\314\201 ERROR warning SUCCESS https://example.invalid 192.0.2.10\n'
for p in 10 50 100; do printf '\r\033[2K进度 %s%%' "$p"; sleep 0.3; done
printf '\nLINE_A\nLINE_B\n'
printf '\033[?1049h\033[2J\033[HERROR alternate'; sleep 2; printf '\033[?1049l'
python3 -c 'for i in range(50000): print("QT_LOAD_%05d" % i);'
```

最后一条只输出编号行，预期末尾 `QT_LOAD_49999`。终端滚动缓存有限，不要求保留全部 50,000 行；检查末尾连续性、结束后的输入响应和异常日志。自动化已有更严格的传输/流控检查。

T05 可使用以下专用会话，前提是测试机已有 tmux/screen。只在受控测试机 shell 执行，记住本次生成的目录：

```sh
QT_QA_DIR=$(mktemp -d /tmp/quayterm-qa-XXXXXX)
mkdir -m 700 "$QT_QA_DIR/screen"
tmux -S "$QT_QA_DIR/tmux.sock" -f /dev/null new-session -s quayterm-qa
# 在 tmux 中 Ctrl+B c / n / p，Ctrl+B d 分离，再从父 shell 重新附着
tmux -S "$QT_QA_DIR/tmux.sock" attach-session -t quayterm-qa
# 再次分离后，在父 shell 启动 screen
SCREENDIR="$QT_QA_DIR/screen" screen -c /dev/null -S quayterm-qa
# 在 screen 中 Ctrl+A c / n / p，Ctrl+A d 分离，再重新附着
SCREENDIR="$QT_QA_DIR/screen" screen -r quayterm-qa
```

在父 shell 和各复用器窗口里分别用 `tty`、`stty size` 与唯一输出标记记录 PTY/尺寸；调整窗口后再次检查。鼠标模式可在该专用 tmux 服务中设置 `set -g mouse on`。结束后只终止这个 socket 的 tmux 服务和这个 `SCREENDIR` 下的会话，再清理核实过的目录；不能终止其他服务。示例不自动安装远端工具。

**F05：用本地程序打开（新增功能构建必测）**

- 在本地列表、双栏 SFTP、终端文件树中右键单个文件，确认菜单包含“用本地程序打开”；文件夹不提供此动作，多选不会误开一个文件。
- 本地文件打开原文件；远端文件下载到独立临时目录，扩展名正确，内容哈希与源文件相同，系统默认程序实际显示文件。记录具体程序和版本；替换 `shell.openPath` 的自动化只能覆盖调用边界，不能替代实际应用显示证据。
- 对二进制、PDF、非 UTF-8 文件双击应走外部打开；对普通文本双击仍进入内置编辑器，连续保存保留 BOM/CRLF；超过 2 MiB 的文本保留编辑限制，但右键外部打开可用。
- 重复打开、不同主机同名文件分别产生独立副本；在外部程序修改副本不会自动写回远端。取消/下载失败不启动外部程序，不保留该次未完成下载；无默认程序时有可理解错误并清理失败副本。
- 权限错误、文件被删除、断连不能误触发外部打开。成功打开的副本在关闭 QuayTerm 后仍供外部程序使用；本轮测试结束后仅清理已确认的测试副本。
- F03 的同名上传还需通过 UI 验证：默认未勾选覆盖、取消不写入、未勾选时保留原文件并报错、明确勾选才替换，下一次确认重新回到未勾选。文件夹中的同名文件同样受后端保护。

不含新功能的历史发行包（含 v0.2.2 原资产）对 F05 标 `N/A：此版本尚未实现`；包含新功能的受测构建不能使用这一理由跳过。

密钥/证书认证、Telnet、串口、保管库和云同步不在当前需求范围，不因缺这些功能判失败。必要依赖/账号缺失应是 BLOCKED；“该功能本来不支持”不能拿来排除核心需求。如果用户要求某项扩展，该项转为该任务的必测，报告注明范围变化。

## 4. 完成判定

**一个平台/架构的核心验收完成**必须同时满足：

1. 上述 A01、R01–R03、H01–H02、P01、T01–T05、F01–F05、N01、Q01 的所有适用子项均为 PASS；真正不适用的分支有 N/A 理由。没有 FAIL、BLOCKED、NOT_RUN 或被隐藏的未完成子项。
2. 各发行格式有 R01/R02 证据，核心功能确实在该 OS/架构的已打包程序上执行；真实 tmux 和 screen 均被验证，真实系统剪贴板和密码重启也被验证。
3. 每项结果绑定代码和产物，修复后的受影响项完成复测；没有以旧版本、另一架构、模拟器或源码运行顶替目标结果。
4. 未解决缺陷和扩展限制已列明；如发现凭证泄漏、数据破坏或核心流程故障，即便出现在扩展场景，也不能声称无条件通过。其他扩展未测可保留，但只能说“核心验收完成”，不能说“完整兼容”。
5. 报告和脱敏证据可复核，清理检查完成；有推送授权时已推送报告和必要修复，记录提交。

**跨平台核心验收完成**还要求 Linux x64、Windows x64、macOS arm64、macOS x64 四行都满足以上条件，并针对同一代码版本；各自生成的二进制哈希自然可以不同。如果只有 Windows 完成，就写“Windows x64 核心验收完成，其余平台见表”，不要写“三端全部完成”。

测试执行完毕但有失败/阻塞时，可写“本轮执行结束”，必须给出通过数、失败/阻塞/未执行项及下一步。把所有任务打勾、构建成功、CI 绿色、截图看起来正常都不是单独的完成条件。

D01 独立于核心功能验收。未签名版本可用于已明确标注限制的私有测试发布；不能把核心通过提升为“正式签名发行验收完成”。
