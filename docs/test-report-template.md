# QuayTerm 原生测试报告模板

复制本文件到 `docs/test-reports/YYYY-MM-DD-<os>-<arch>-<version>.md`（目录不存在时创建，重名时加轮次后缀），替换占位字段，并将下方验收清单链接改为 `../test-acceptance.md`。不同机器/轮次不要覆盖同一份报告。原始日志放本机 `.private/qa/<run-id>/`，提交前将需要共享的证据脱敏。不能用本模板本身作为执行证据。

## 环境与目标

- 日期/时区、测试人员或 agent：〈填写〉
- 目标与范围：〈系统/架构、核心或用户指定扩展；写出未覆盖范围〉
- OS 版本/build、CPU 与实际进程架构：〈是否原生；是否 Rosetta/虚拟机〉
- 桌面/显示器/缩放、输入法/键盘：〈填写〉
- 文档提交、受测源码提交：〈两个完整 SHA〉
- 受测 Release / 修复构建：〈链接/来源、版本、构建提交〉
- Node/npm/Electron 版本：〈填写〉
- 受测程序的实际路径、启动参数：〈脱敏；说明正常入口/自动化启动、是否添加沙箱参数〉
- 配置隔离：〈测试 OS 账号、QUAYTERM_DATA_DIR；禁止写入凭证〉
- 密码存储：〈backend 或系统机制、可用性、跨新进程解密实测结果；不得贴密文〉
- 测试服务：〈匿名代号、OS/SSH/SFTP/tmux/screen 版本、临时目录/操作授权范围〉
- 远端指纹依据：〈独立核实渠道/测试服务已知密钥；不能仅填自动信任报告〉

## 自动化结果

| ---------------- | -------- | ----------------- | ------------------ |
| 〈实际执行命令〉 | 〈数值〉 | 〈实际数值〉      | 〈脱敏记录〉       |

仅列实际执行的命令；记录开始/结束时间。区分本轮结果与引用的历史 CI。packaged 脚本还需确认报告非空且覆盖全部预期主机，记录成功数量，不粘贴真实账号。

## 缺陷、阻塞和复测

每项复制一组字段；没有则明确写“无”，不要保留虚构示例：

- 编号、关联用例、状态/严重程度：〈填写〉
- 可复现步骤、预期、实际、频率：〈填写〉
- 影响：〈数据/凭证/连接/界面等实际影响，不凭空判断〉
- 证据：〈脱敏日志/截图/哈希；仅本机文件需标明并提供可共享摘要〉
- 原因或缺失条件：〈已确认事实与推测分开〉
- 修复提交或解除条件：〈填写〉
- 复测产物哈希、命令/步骤、结果：〈填写；保留首次失败记录〉
- 尚需谁提供什么：〈明确下一步；不要仅写“以后再测”〉

## 清理与结论

- 本次应用/SSH/SFTP/测试服务/专用 tmux 和 screen：〈已关闭或剩余对象及原因〉
- 临时文件、part 文件、配置、剪贴板：〈已检查/清理；只处理本轮测试资源〉
- 用户原有数据与会话：〈未改动；若有异常如实写明〉
- 报告/证据脱敏、暂存差异检查：〈结果〉
- 核心统计：PASS 〈n〉 / FAIL 〈n〉 / BLOCKED 〈n〉 / NOT_RUN 〈n〉 / N/A 〈n〉；子项：〈另列，不重复累计父项〉
- 本平台结论：〈核心验收完成 / 本轮执行结束但未完成；按完成标准说明依据〉
- 其他平台状态：〈引用已有对应报告；没有证据不得填 PASS〉
- 下一位 agent 从哪里继续：〈具体 ID、所需机器/服务和操作〉
- 报告/修复推送：〈分支、提交或提交链接；未获推送授权则说明本地位置〉
